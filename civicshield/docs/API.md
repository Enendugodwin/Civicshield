# API

Base `/api`. Health `GET /api/health` (includes AI status). Demo account: `GET /api/me` (username, role, permissions; the `X-Role` header is a demo control, not production authentication).

Auth: `Authorization: Bearer <token>` demo tokens or `X-Role: admin|operator|viewer`. Viewer is read-only; writes need operator, deletes/admin actions need admin.

- Assets: `GET/POST /api/assets`, `GET/PATCH/DELETE /api/assets/{id}`, `POST /api/assets/import` (`{csv_text, dry_run}`; 200-row / 256 KB limits, duplicate detection, preview-before-accept). `GET /api/assets/{id}/evidence` returns stored evidence and collection metadata; `POST /api/assets/{id}/evidence` accepts a read-only collector payload (operator role). New devices start with empty evidence and are reported as `UNKNOWN` until collected.
- Services: `GET /api/services`.
- Relationships: `GET/POST /api/relationships`, `DELETE /api/relationships/{id}` (duplicates rejected 409). `provenance`/`evidence_ref` are exposed for import tracking.
- Architecture checks: `GET /api/architecture/checks` (read-only preview of AR-* structural hits), `POST /api/architecture/checks/raise` (`{rule_ids?}`; operator; idempotent upsert of `architecture`-source findings with risk scores, reopens still-failing resolved findings, resolves stale ones).
- Attack-path analysis: `POST /api/analysis/attack-paths` (`{entry_asset_id?, target_asset_id?, max_depth? (1-8), max_paths? (1-10), exclude_edge_ids?, exclude_asset_ids?}`; read-only, recomputed live every call). Returns ranked entry-to-target paths with per-hop relationship evidence, connectivity labels (confirmed/configured/inferred/hypothetical), plain-language assumptions, trust-boundary crossings, open findings on path nodes, blast radius, and transparent rank factors. Exclusions enable before/after comparison of a proposed defensive cut.
- Agent team: `GET /api/agents` (13-agent registry with capabilities, tool allowlists, I/O schemas, budgets), `POST /api/agents/investigations` (`{kind, ref?}`; operator; deterministic routing, bounded synchronous execution with per-task attempts/timing, merged summary, at most one shared-model synthesis call), `GET /api/agents/investigations[/{id}]`, `POST /api/agents/investigations/{id}/cancel` (operator; 409 when nothing is running). Specialists are read-only; write actions stay behind chat approval.
- Change proposals: `POST /api/architecture/proposals` (`{title, rationale?}`; operator; staged only), `GET /api/architecture/proposals[/{id}]`, `POST /{id}/changes` (`{op: remove_edge|add_edge|update_asset, payload}`; validated eagerly, draft only), `DELETE /{id}/changes/{cid}`, `POST /{id}/simulate` (`{must_block?, must_keep?}`; before/after AR hits + attack paths on a snapshot copy, verification outcomes, results labeled simulation), `POST /{id}/approve` (operator; needs simulated), `POST /{id}/apply` (operator; needs approved; writes live records with audit), `POST /{id}/reject`.
- Detection: `POST /api/detect` (`{asset_ids?, online?}`), `POST /api/assets/{id}/detect`, `GET /api/detection/posture` (evidence coverage, advisory snapshot, last run). Detection combines the deterministic BaselineGuard controls with version-based CVE matching; only FAIL controls and vulnerability matches become findings.
- Assessments: `POST /api/assessments/run` (upserts findings by rule+asset, reopens still-present resolved findings), `GET /api/assessments` (includes `scope`), `GET /api/assessments/{id}` (+`/export?format=json|csv`, CSV formula-injection guarded).
- Findings: `GET /api/findings`, `GET /api/findings/{id}`, `PATCH /api/findings/{id}` (`workflow: open|acknowledged|investigating|resolved|false_positive`, assignee, reason required to resolve/dismiss), `POST /api/findings/{id}/explain`, `POST /api/findings/{id}/remediation-plan`.
- Risk & impact: `GET /api/risk/{finding_id}` (score, factors, model version), `GET /api/impact?asset_id=` (downstream assets, affected services counted once by ID with dependency paths), `GET /api/identity` (privileged-account inventory, MFA coverage with unknown-not-disabled rule).
- Remediation (single FixPilot API): `POST /api/remediation/propose|/{id}/approve|/{id}/simulate|/{id}/verify|/{id}/reject|/{id}/reopen|/{id}/apply|/{id}/task` (task sets owner/due-date/note, audit-logged, never moves lifecycle state), `GET /api/remediation/{id}/audit`, `GET /api/remediation/ai/status`. All mutating calls require operator role. The old `/api/remediation-plans/*` aliases are removed. Expensive AI endpoints are rate-limited (429 + Retry-After).
- Recovery: `POST /api/recovery/scenarios` (7 scenarios incl. gateway/monitoring/backup loss, dual failure), `POST /api/recovery/runs`, `GET /api/recovery/runs/{id}`, `GET /api/recovery/readiness` (per-service criteria with failed-criteria listing), `POST /api/recovery/runs/{id}/recommendations` (operator; one FixPilot plan per scenario-failed asset with open findings, cap 5; assets without findings reported honestly).
- Incidents: `POST/GET /api/incidents` (severity, commander), `GET/PATCH /api/incidents/{id}`, `POST /api/incidents/{id}/events` (observed|evidence|interpretation|suggestion|decision), `POST|DELETE /api/incidents/{id}/findings/{fid}`, `GET /api/incidents/{id}/report`, `POST /api/incidents/{id}/summary` (AI with deterministic fallback).
- AI assistant: `GET /api/ai/health`, `GET /api/ai/capabilities`, `GET/POST /api/ai/conversations`, `GET/PATCH/DELETE /api/ai/conversations/{id}`, `POST /api/ai/conversations/{id}/messages`, `GET /api/ai/conversations/{id}/stream` (SSE), `GET /api/ai/conversations/{id}/export`, `POST /api/ai/conversations/import`, `GET/POST /api/ai/tasks/{id}/approve|cancel`. Deterministic intent router over live records; live model rephrases verified context with offline fallback; answers carry `model_used` (live id, `fallback`, or `policy`) plus contextual `followups`; assets are referenced by hostname; CVE lookups enrich with live NVD/CISA context (allowlisted hosts, CVE-gated, TTL-cached, labeled `web-live`/`web-unavailable`); tool advice splits open-source vs commercial with explicit scope limits; write tools need operator role and chat approval; idle conversations expire after 24h (410 on write, history stays readable).
 - Detection drafts: `GET/POST /api/detection/rules` (operator; `rule_id` must match `DR-*`, predicate kinds `evidence_missing|equals|in|gt|lt|contains` over dotted evidence paths), `GET/PATCH /api/detection/rules/{id}` (PATCH draft-only), `POST /{id}/test` (dry-run preview with per-asset FAIL/PASS/UNKNOWN, never writes findings), `POST /{id}/activate` (operator; honors dual-control policy), `POST /{id}/retire` (terminal; next detection run resolves orphaned findings). Active drafts run inside every detection pass.
 - Continuous protector: `GET /api/protection/status` (enabled, interval, pending queue, unacked count, last run), `POST /api/protection/run` (operator; trigger recorded as scheduled|event|manual), `PATCH /api/protection/config` (operator; `enabled`, `interval_seconds` 60-86400, `keep_runs` 5-500, `notify_retention_days` 1-365), `GET /api/protection/runs`, `GET /api/protection/notifications` (`unacked_only`), `POST /api/protection/notifications/{id}/ack` (operator, explicit). Estate mutations (assets, relationships, imports, evidence) enqueue non-blocking event reassessments; a daemon scheduler re-runs on the interval.
 - Governance: `GET/PATCH /api/governance/policies` (admin for writes; `require_distinct_approver` blocks self-approval of drafts when on), `GET /api/governance/audit-verify` (read-only SHA-256 chain check over all audit events), `GET /api/governance/migrations` (schema version + per-migration applied state). The audit log is append-only (no PUT/DELETE routes). Startup applies pending migrations from `app/migrations.py` (idempotent, `schema.version` recorded).
 - Demo environments: `POST /api/demo/reset` (admin; `{"env": "a"|"b"|"c"}`) wipes the estate and seeds a reproducible fictional environment — a) community water utility (13 assets), b) Cloud SaaS (8 assets, excessive-permission + public-access weakness), c) hybrid enterprise (7 assets, weak cross-trust + untested backups). Records `demo.env`.
- Threat intel: `GET/POST /api/threat-indicators` (duplicates rejected 409, expiry flagged), `GET /api/threats/exposure` (bundled advisories vs declared asset software: confirmed/potential/unevaluated + rules-based recommended action), `POST /api/threats/analysis` (operator, rate-limited; AI plan stored in FixPilot queue, 404 on unknown advisory), `GET /api/assets/{id}/threats` (advisories affecting one asset with match evidence), `GET /api/threats/sync-status` (feed health, never-synced setup note), `POST /api/threats/sync` (operator, rate-limited; OSV.dev refresh of declared software, failures recorded with ok=false).
- Reports: `GET /api/reports/posture` (executive summary with provenance metadata), `GET /api/reports/assessment` (CSV), `GET /api/reports/recovery` (JSON), `GET /api/reports/threats` (JSON, `?format=csv` with formula-injection guard). `GET /api/audit`.
- Evidence review: `GET /api/review/posture?focus=all|vulnerability|identity|backup|network&audience=technical|executive` returns counts, top findings, readiness, recommendations and a markdown review. This is the review used by the MCP server; it is deterministic and does not invent evidence.
- Demo: `POST /api/demo/reset` (reseed deterministic baseline).
